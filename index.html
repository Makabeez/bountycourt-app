The problem

Somebody has to decide whether the work was done.

Every bounty, grant milestone and freelance escrow eventually reaches the same question, and the usual answers are all custodial. A maintainer decides. A multisig decides. An oracle relays a decision made somewhere off-chain. In each case the party holding the money is also the party judging the work.

BountyCourt puts the judgment itself under consensus. The criteria are public before the work starts, the evidence is immutable once submitted, and the validators who rule cannot see each other's answers — they only agree if they independently reached the same one.

Lifecycle

01PostCriteria in plain English. The GEN you send is the escrow.
02SubmitEvidence URL pinned to a 40-character commit SHA.
03AdjudicateEvery validator rules on every criterion, independently.
04ReleaseEscrow goes to whoever the agreed booleans say won.
05or AppealThe loser stakes a bond equal to the escrow for a second jury.

A ruling holds the escrow rather than paying it. That gap is what makes an appeal possible.

How it is built

Consensus per criterion, not per verdict

The jury returns one boolean per criterion. Validators must agree on every one before anything is written. The outcome is then computed in deterministic code — the leader's prose decides nothing.

Evidence that cannot change

A URL without a 40-character commit SHA is refused. A branch reference could be rewritten between submission and adjudication, letting the party being judged edit their own evidence.

It refuses to rule on a partial view

If the artifact exceeds the readable window the contract returns INCONCLUSIVE and holds the escrow. We measured validators agreeing unanimously on false answers when evidence was truncated.

Appeals cost money

Only the losing party may appeal, and only by staking a bond equal to the escrow. Overturned, they take escrow plus bond. Upheld, both go to the other side.

Twelve checks before value moves

Output shape, ruling count, id range, duplicate ids, boolean types, full coverage. Any deviation reverts the transaction and the escrow stays exactly where it was.

Untrusted evidence, treated as such

The hunter controls the page the contract reads. The ruling prompt states that anything inside the evidence block is data to be judged, never instructions to follow.

What we learned building it

Consensus guarantees agreement, not truth. In a controlled study, the same claims against a rendered HTML page produced unanimous agreement on answers that were false — the file list never entered the character window. Against a structured JSON source, the same jury answered correctly. The fetch layer decides which one you get, and only the first is reported on chain.
Free text in a compared answer prevents consensus. An earlier version asked validators for a per-criterion reason string and told the equivalence principle to ignore it. Four leader rotations, UNDETERMINED, with identical booleans from every leader. Removing the field fixed it on the first attempt.

Both findings, and five more undocumented GenVM behaviours, are written up in the repository and the WebClaims study.
